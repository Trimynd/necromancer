Four modes, one pipeline

Every stage of a company's life

The user picks where they are on the curve, or the AI preselects it from their pitch or document. The mode changes the questions, the attack and the signature section. The pipeline stays the same.

The pipeline

What happens, step by step

Eight steps from first words to final verdict. Blue steps involve the user, teal steps are Gemma thinking, green is the agent team, red is the attack.

  1. 1

    User

    Pitch and pick a mode

    The user describes the business in a paragraph, uploads documents, or both. The AI preselects one of the four mode cards and the user confirms with one click.

    Sees: text box · upload area · 4 mode cards · sample companies

  2. 1b

    Gemma

    Document understanding

    Uploaded files become facts before any question is asked. One Gemma call maps a PDF to profile fields and a suggested mode. Spreadsheets are read by plain code, because numbers must be exact.

    From "CompanyProfile.pdf" + "sales.csv" I learned:

    ✓ 12 months of sales: ₹18L → ₹9Lsales.csv · exact
    ⚠ Team: 6 staffp.1 · please check
    ? Cash in bank: not foundwill ask
    → Mode: Rescue  [Edit] [Looks right →]
    FileHow we read itPriority
    PDF (profile, pitch deck)Sent straight to the model; fallback is text extractionMust
    CSV / Excel (monthly numbers)Plain code, never the AI; feeds the Grow and Rescue chartsMust
    Images (dashboard screenshot, ledger photo)The model reads imagesShould
    DOCX / PPTXText extraction, or ask for a PDFStretch

    Rules: files are processed in memory and never stored · document text is data, never instructions · numbers from a PDF are marked "please check" · max 3 files, 10 pages, 5 MB each

  3. 2

    User + Gemma

    Intake: ask only what's missing

    About six fixed core questions per mode, which the charts and ROI need, then up to four adaptive follow-ups. Each follow-up follows the mode's playbook and shows why it's being asked.

    Example (Rescue): "Are fewer people coming in, or are they coming but not buying?" Asking because it separates a footfall problem from a conversion problem.

  4. 3

    Gemma · Role Maker

    The team is invented, not hardcoded

    Gemma reads the profile and decides how many agents to create, what each is called and what it researches. One rule: every report section must be covered by at least one agent.

  5. 4

    Agent team · in parallel

    Research with sources

    Each agent searches the web for its own task, keeps every source link and reports in the same shape: core assumption, evidence for and against, risks tagged external, internal or assumption, and countermeasures.

    Sees: live status per agent (searching, reading, analysing, done) and a live feed of findings

  6. 5

    Devil's advocate

    One call tries to kill the plan

    It reads every finding, writes the strongest argument against, picks the riskiest assumption and says whether the plan survives. The attack depends on the mode; pick a mode above to see it.

  7. 6

    Gemma · Synthesis

    Merge, resolve, score

    Combines the findings and the attack, resolves contradictions, scores six dimensions and writes the verdict.

  8. 7

    Report

    The same sections every time

    The agents change with every business; the report doesn't. Synthesis maps whatever they found onto a fixed set of sections, shown below.

Credibility

Rules for numbers

Judges will push hardest on ROI. An AI inventing a single "240% ROI" won't hold up, so these five rules apply everywhere.

Code does the maths

Gemma estimates assumptions. Plain code calculates break-even, ROI and LTV:CAC.

Show the assumptions

Each one marked "from you", "from research" with a link, or "AI estimate".

Make them sliders

The user corrects any assumption and the verdict updates instantly in the browser.

Ranges, not one number

"ROI 18–35% by year 2, break-even in months 14–20."

No uncited statistics

If we can't link it, we don't say it, in the product or in the pitch.
